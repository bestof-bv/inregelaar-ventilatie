# Inregelaar Ventilatie — установка на Android

Размещение: **GitHub Pages** (бесплатно для публичного репозитория). Адрес вида `https://<имя-пользователя>.github.io/<репозиторий>/`. Обновление: загрузить файлы новой версии в репозиторий (GitHub → Add file → Upload files) — через 1–2 минуты сайт обновится. Прежний адрес на Netlify (airbalansingapp.netlify.app) больше не используется.

Приложение для пусконаладки вентиляции: первичный замер, регулировка арматуры по пропорциональному методу, контрольный замер и отчёт (inregelrapport) в Excel и PDF на нидерландском (бельгийская терминология) или французском. Интерфейс — английский, нидерландский или русский. Работа бригадами через пакеты. Работает без интернета.

## Что в папке

| `.nojekyll` | для GitHub Pages: файлы отдаются как есть |

## Как поставить на телефон

Приложение должно открываться по адресу `https://…` — так Android разрешает установку и офлайн-режим. С обычного `http://` (и с файла на диске) офлайн-кэш не регистрируется: приложение работает только при наличии сети и не ставится на главный экран.

1. Разместите папку `inregelaar-ventilatie` на любом бесплатном хостинге статических сайтов, например:
   - **GitHub Pages** — публичный репозиторий, файлы из папки `inregelaar-ventilatie` в его корне (включая пустой файл `.nojekyll`), Settings → Pages → Deploy from a branch → `main` / `(root)`;
   - любой другой хостинг статических файлов с https (Cloudflare Pages, Netlify и т. п.) — те же файлы в корень сайта.
2. Откройте адрес в Chrome на Android.
3. Меню ⋮ → **Установить приложение** (или «Добавить на главный экран»).
4. Откройте приложение один раз с интернетом — дальше оно работает офлайн, включая формирование PDF и Excel.
5. Обновление: выложите новую папку на тот же адрес. При запуске с интернетом приложение сразу берёт новую версию (сначала сеть, потом кэш); без сети открывается последняя сохранённая.

## Данные

- Проекты хранятся в памяти телефона (браузерное хранилище приложения).
- На шаге «Отчёт» есть **Резервная копия (.json)** — сохраняйте её после каждого объекта. Этот файл открывается на другом устройстве через «Импорт .json».
- Если удалить приложение или очистить данные Chrome, проекты без резервной копии пропадут.

## Фото и примечания

- На каждой странице (шаге) есть блок «Примечания и фото к странице», у каждой точки и установки — своё примечание и фото.
- Кнопки «Камера» и «Файл / PDF»: JPEG, PNG, WebP, GIF, SVG и PDF (выбранные страницы PDF становятся изображениями). Фото сжимаются до 1600 px, чертежи и скриншоты остаются в PNG. HEIC браузер не читает — на камере включите JPEG.
- Нажатие на миниатюру — просмотр, подпись (bijschrift) и удаление.
- В отчётах всё это собирается в раздел «Opmerkingen en foto's» (PDF — отдельная глава, Excel — отдельный лист с фото).

## Исполнитель в отчёте (0.9.7)
- Имя техника у каждого замера («Gemeten door» в Excel, в примечании PDF) печатается только при работе бригадами: если замеры сделали два и более техника или две и более бригады. Если весь отчёт заполнил один человек, эти строки не печатаются. Шапка «Technicus» и подписи «Uitgevoerd door» остаются.

## Исправления (0.9.8 — исправлено в 0.9.9)
- Суммы «Σ eindorganen» в отчёте: конечным потоком считается точка без подчинённых (решётка, а также VAV/CAV/ирис в конце ветки). Раньше учитывались только решётки, и суммы не сходились с балансом luchtgroep. Линейные демпферы и измерение главного канала в суммы не входят. Формулы Excel (колонка «Soort») используют то же правило.
- Excel: код luchtgroep с символами `*`, `?`, `~` или кавычкой больше не ломает формулы Σ (SUMIFS/COUNTIFS).
- Имя техника и ploeg сравниваются точно, без совпадения по части строки.
- Результат ploeg: значения, измеренные до даты выдачи пакета, не объединяются. Если такое значение отличается от мастера, появляется предупреждение (проверьте часы устройства бригады).
- Импорт замеров из Excel: значения разделяются «;», «|», «/» или пробелом («120 130 125» — три замера). Пробел внутри числа с десятичной частью — разделитель тысяч («1 200,0»).
- Лист замеров (Excel): при печати запоминается состояние проекта. При возврате объединяются только значения, которые бригада изменила на листе. Изменения координатора, сделанные после печати, не откатываются.
- Если в листе метод не распознан, появляется предупреждение; замеры этой строки не читаются молча.
- Новые точки с неизвестной ВУ не добавляются в проект и в пакет, а в сводке показываются.
- Сохранение: при полном хранилище изменения остаются помеченными и не теряются. Параллельные обновления входа используют один запрос. Отказ в обновлении входа завершает сессию и её права.
- Σ-строки Excel: счёт измерений и сумма по ОУ совпадают с приложением (учитываются нулевые расходы; производная проектная сумма — только когда есть данные у всех подчинённых).

## Импорт из Excel

- Шаблон: кнопка «Шаблон Excel для импорта» на главном экране или на шаге «Точки» (файл `Inregelaar_importsjabloon.xlsx`).
- Листы Project, Meettoestellen, Luchtgroepen, Meetpunten с выпадающими списками. Строки с кодом на # — примеры, не импортируются.
- Колонка «Master» — код вышестоящего узла (та же установка и направление); «p stat vóór / na» — статическое давление, «Δp min» — минимальный перепад регулятора.
- Также распознаются таблицы «Inregelen» (Aerolish-opstartrapport, включая «Statische druk voor / na») и «Swegon» (meetRapportLucht).
- Главный экран → «Импорт .json / .xlsx» создаёт новый проект; шаг «Точки» → «Импорт из Excel» добавляет точки в открытый проект.

## Обложка отчёта

Шаг «Проект» → «Обложка отчёта»: главное изображение и два малых, как на обложке буклета. Источник — фото или страница PDF (например, план); после выбора задаётся кадр (перетаскивание и масштаб). Подписи, заголовок, подзаголовок и строка в синей полосе редактируются там же. Пустые места заполняются фото из примечаний к проекту или сводкой по установкам.

## Стиль отчётов

Стиль отчёта задаётся в «Настройках → Фирма в отчётах → Стиль отчёта». Встроен стиль **Fresh Air**: хвойный #0F3D3E, зелёный #2A9D6F / #1E7A55, голубой #1D6E99, светло-голубые ячейки ввода, у каждого этапа своя полоса (REFERENTIE · ONTWERP · INREGELING · CONTROLE · OPMERKING), логотип inregelaar (дом с притоком и вытяжкой), слоган «Fresh air, zero waste». Шрифт — Arial / Liberation Sans.

Стиль фирмы — отдельный файл `*.inregelstijl.json` (цвета, логотип, слоган и, по желанию, реквизиты фирмы). Кнопка «Добавить стиль из файла» загружает его; если в файле есть реквизиты, приложение предложит заполнить ими поля фирмы. «Сохранить как файл стиля» записывает текущий стиль вместе со своим логотипом и реквизитами — этот файл можно передать коллегам. Стиль Matthijs nv лежит в папке `styles/` этого архива — `styles/matthijs-nv.inregelstijl.json` (тёмно-синий #262157, оранжевый #FF6A13, кремовые ячейки, логотип и реквизиты Matthijs). Свой логотип, по-прежнему, можно загрузить в «Настройках» — он заменяет логотип стиля.

**Страница стиля.** «Настройки → Стиль отчёта → Настроить стиль» открывает страницу Fresh Air: цвета, полосы этапов, элементы таблицы, шапка и подвал. Нажатие на образец цвета, на текст или на логотип меняет его; изменения видны сразу. «Сохранить как свой стиль» создаёт копию встроенного Fresh Air (свой стиль сохраняется на месте), «Сохранить как файл стиля» — файл `.inregelstijl.json` для коллег. Смотреть страницу может каждый, менять и сохранять — только владелец и администратор (право «Фирма, логотип и подвал»).

**Обложка PDF.** Логотип и слоган, до трёх фото (большое и два малых, с подписями), заголовок, проект и адрес, четыре плитки (проект, замер после наладки, % от проекта, точки в допуске) и тёмная полоса с фирмой, адресом и подвалом. Пустые места фото занимает панель с группами.

**Таблицы.** Полосы этапов в цветах стиля, светлые строки групп, ячейки ввода, проценты вне допуска — тёплым цветом, в допуске — зелёным, статус — «пилюлей»; над таблицей — сводка по группам, под ней — легенда.

**Демо и первый вход.** Данные фирмы по умолчанию вымышленные (Voorbeeld Klimaattechniek bv), стиль Fresh Air. Демо хранит свои настройки отдельно, поэтому реквизиты фирмы на устройстве в демо-отчёт не попадают.

## Как пользоваться

1. **Проект** — номер, объект, заказчик, наладчик, дата, приборы с датой калибровки, допуски (по умолчанию ±10 %).
   У прибора список **«Из паспорта»** заполняет вид, диапазон, точность и ссылку по официальным паспортам производителей: TSI ProHood PH731; testo 417 и 417 + testovent 417; testo 512 (2 и 20 hPa); testo 440 dP (дифманометр, с трубкой Пито 0635 2045) и testo 440 с зондами — крыльчатка Ø100 мм (0635 9431/9432), высокоточная Ø100 мм от 0,1 м/с (0635 9371/9372), Ø16 мм (0635 9571/9572), термоанемометр (0635 1571/1572), крыльчатка Ø100 мм + testovent 417. Значения для testo 440 — по [паспорту 1981 1214 (10.2026)](https://static.testo.com/image/upload/HQ/testo-440-datasheet-1981-1214.pdf); в бельгийском паспорте 1983 1214 (08.2021) у термоанемометра 0635 1571/1572 было 0…50 м/с, сейчас 0…30 м/с. Если имя прибора было просто названием вида («Debietkap»), при выборе паспорта другого вида оно меняется.
2. **Точки** — установки (luchtgroepen) с проектными расходами; узлы (CAV, VAV, IRIS, регистр ветки, воздуховод), решётки, арматура. Кнопка «Серия» создаёт сразу T1.01…T1.10, в т. ч. сразу под выбранным узлом.
   **k-фактор клапана / решётки** (метод «Δp × k-фактор»): у точки выбирается единица k — для Q в м³/ч или в л/с (Q = k·√Δp). У ирисового клапана по умолчанию л/с, у остальных — м³/ч; при смене единицы введённое число остаётся, меняется только единица. В расчётах и в отчёте k хранится и выводится в м³/ч (колонка «k-factor (m³/h·Pa⁻⁰·⁵)»). Старые проекты открываются с единицей м³/ч — значения не меняются. Импорт: колонка «k-factor (l/s)» или «k iris» читается как л/с. В замерочном листе бригады k стоит в единице точки (подсказка в колонке «Meetmethode»).
3. **Замер 1** — параметры установки и все точки по дереву; положение арматуры до регулировки; статическое давление в воздуховоде перед узлами и у дальних решёток.
   **Этаж, помещение, порядок (0.9.5)**: над списком точек фильтры «Этаж / зона» и «Помещение» (lokaal) сужают список; переключатель «По установке / ветке» (по умолчанию) или «По этажу / помещению». Во втором режиме точки идут по этажу / зоне, затем по помещению, внутри помещения сначала приток, потом вытяжка — одно помещение замеряется за один проход. Каждое помещение — отдельный блок с проектным расходом «T … · A …». Точки без этажа идут в конце; помещение другого этажа сбрасывается при смене этажа.
4. **Арматура** — индекс системы по давлению, группы балансировки снизу вверх (решётки под каждым IRIS → IRIS под CAV → ветки), калькулятор регулировки, ориентировочная частота вентилятора; положение после регулировки, фиксация, состояние противопожарных и запорных клапанов.
   **Порядок групп**: снизу вверх по иерархии, а внутри одного уровня — от самой перегруженной группы (наибольшее отношение факт/проект) к индексной, которая идёт последней; на карточке видно «n из N на уровне» и Σ % группы. В карточке «баланс ветвей» ветви стоят в том же порядке с номером, отношение считается только по точкам, где есть и замер, и проект.
   **Калькулятор группы**: после ввода «индекс сейчас» показывается цель для регулируемой точки в м³/ч — Qцел = Qпроект,точки × Qиндекса сейчас / Qпроект,индекса (то же отношение, что у индекса в этот момент); для точки с k-фактором — и Δp на штуцерах при её k, для анемометра — скорость при её Ak. С вводом «эта точка сейчас» — подсказка «прикрыть / открыть / сбалансировано» (±5 %).
   **Частота вентилятора**: после регулировки ветвей замерить индексную точку (★, она оставалась открытой) и ввести её расход и частоту в этот момент — программа считает f₂ = f · Qпроект / Qиндекса. Без этого показывается грубая оценка по первичному замеру (обычно занижена, потому что клапаны потом прикрыты).
5. **Замер 2** — контроль, отклонение и OK/NOK по допуску.
6. **Отчёт** — язык отчёта (NL / FR), проверка полноты, вывод (кнопка составляет текст на языке отчёта), подпись, Excel и PDF.
   **Помещения**: решётки с одинаковым названием помещения складываются по стороне (приток / вытяжка) и сравниваются с проектом; допуск «Помещение ±» в проекте, по умолчанию 15 % (EN 12599:2012, табл. 3: ±15 % на помещение и ±10 % на систему — это допустимая погрешность замера). Карточка «Помещения» на шаге «Отчёт», лист Excel «Ruimten», таблица и итог в разделе 5 записки, фраза в заключении. Помещение с незамеренной решёткой или без проектного расхода — «неполное».

## Чек-лист ввода в эксплуатацию (Checklist inbedrijfstelling)

21 пункт: 20 из шаблона и пункт 8 «двери, окна, люки закрыты, установка в проектном режиме (VAV на максимуме)». Порядок снизу вверх, как в пропорциональном методе: 14 — решётки по ветвям, 15 — ветви и магистрали между собой (в шаблоне было наоборот). Один общий список на проект и дополнение по каждой установке (luchtgroep). Ответы: ja / nee / n.v.t.; без ответа — «niet ingevuld».

- **Меню установки** (Точки → установка): пункты 4 (направление вращения), 6 (калориферы / охладители) и 8 (помещения закрыты, проектный режим) — до первого замера этой установки. Пока они не отмечены, в первом замере над данными установки висит напоминание, а при первом вводе показаний — подсказка. Замеры это не блокирует.
- **Табличка и паспорт** в том же меню: номинальный ток, класс фильтра (ISO 16890), начальный и конечный Δp фильтра, калориферы, метод общего расхода. При методе «давление на конусе + k-фактор» в замерах вводится давление на конусе. Формула k-фактора на выбор: **Q = k·√Δp** (большинство вентиляторов; k для Q в м³/ч или л/с) или **Q = k·√(2·Δp/ρ)** (установки Trane; k в м², Q в м³/с, ρ — плотность воздуха проекта из «Допуски и параметры»). Рядом с замером видно давление на конусе для проектного расхода; формула попадает в записку и чек-лист.
- В замерах установки добавлены статическое давление на всасывании и на нагнетании (отдельно от внешнего давления).
- **Автоматически** заполняются пункты 5, 7, 9–11, 13–18 и 20 — с основанием (токи против таблички, Δp фильтра, индекс по давлению, расходы, доля точек в допуске, положения клапанов, баланс). Любой ответ можно изменить; «вернуть авто» снимает ручной ответ. Своё замечание к авто-ответу ответ не меняет.
- **Перед отчётом** (кнопки Excel / PDF) открывается окно с пунктами 1–3, 12, 19, 21 и всем, что осталось открытым. Можно ответить или сформировать отчёт с открытыми пунктами. «nee» без замечания не принимается.
- **В отчёте**: лист Excel «Checklist inbedrijfstelling» (с колонкой «Bron»: auto / handmatig) и страница PDF после клапанов; * у ответа = заполнено автоматически. Бригады в своих пакетах чек-лист не ведут.

## Пояснительная записка (Toelichtende nota) и заключение

## УВУ и системы из нескольких УВУ (0.9)

- **Тип УВУ** (карточка УВУ): приток и вытяжка / только приток / только вытяжка; для приточно-вытяжной — рекуперация (пластинчатый, роторный, гликолевый контур, тепловая трубка, без рекуперации). Однонаправленная УВУ показывает только свою сторону: проектный расход, замеры, точки, чек-лист.
- **Система**: в карточке УВУ «Объединить с …» соединяет УВУ в одну систему. Тип связи: каскад (основная питает вторичные — их расход не учитывается дважды; порядок наладки: основная → вторичные → контрольный замер основной), дополнение (например, местные вытяжные вентиляторы), компенсация (подпиточная УВУ под вытяжку кухни или технологии), параллельно / резерв (резервная не учитывается). Роль каждой УВУ: основная / вторичная / дополнительная / компенсирующая / резерв. «Общая сеть воздуховодов» — точки относятся к системе, калькулятор вентиляторов считает УВУ вместе. «Вывести из системы» — снова отдельная УВУ.
- **В списках** система — одна строка («LG02+LG03 · компенсация — Кухня»): фильтр на шагах, выбор УВУ для точки (общая сеть — одна строка), объём отчёта. Под ней — её УВУ.
- **Порядок**: стрелки ↑↓ у каждой системы и кнопка «Упорядочить по коду». Отчёт идёт в этом порядке во всех главах; клапаны на воздуховоде — по УВУ, затем по этажу / зоне.
- **Баланс системы**: в карточке замера каждой УВУ системы — строка «Система …: приток … / вытяжка …, приток − вытяжка …»; в отчёте — таблица системы (приток, вытяжка, разность); пункт 18 чек-листа — по системе.

## Вентиляторы и двигатели (0.9)

- **Список вентиляторов** в карточке УВУ («+ Вентилятор», «Изменить», «Копировать», «Так же для стороны»). У вентилятора: позиция (M1 …), сторона (в т. ч. один двигатель на приток и вытяжку), количество одинаковых, производитель и тип, двигатель (EC / AC / DC), питание (1~230, 3~230, 3~400 В, 24/48 В DC), регулирование (частотный преобразователь, EC-контроллер, две скорости / ступени, ступенчатый трансформатор / симистор, постоянная скорость, ремённая передача, постоянный расход, постоянное давление), шильдик (P, In, U, n, cos φ, класс IE), k-фактор конуса, блок «Управление и связь».
- **EC**: что показывает / задаётся на контроллере — %, В, об/мин, Гц, уставка м³/ч или Па; выбор запоминается для производителя.
- **Замеры по вентилятору**: величина по типу регулирования (Гц, %, В, об/мин, ступень, уставка), мощность с дисплея, давление на конусе (если общий расход по конусу), ток: для 3~ — по фазам L1, L2, L3 (+ напряжения по желанию), иначе одно значение. Строка под замером: Iср, Imax против In, **перекос** = max|I − Iср| / Iср · 100 % против предела проекта (Проект → Допуски: «Перекос тока 3~, макс.» — по документации производителя двигателя), мощность (с дисплея или ≈ √3·U·I·cos φ).
- **Калькулятор** (шаг «Клапаны»): на сеть и сторону — индекс расхода и его расход сейчас, текущая настройка каждого вентилятора; рекомендация по законам подобия (Q ~ n, Δp ~ n², P ~ n³): частота / обороты / уставка расхода ∝ Q, уставка давления ∝ Q², EC-сигнал % / В — приблизительно (проверять по оборотам), ступени — «на ступень выше / ниже», ремень — новый диаметр шкива двигателя. Предупреждения: выше f max / 100 % / 10 В, мощность после ≈ выше номинальной потребляемой (√3·Un·In·cos φ).
- **Отчёт** («Luchtgroepen»): по каждому вентилятору — настройка до / после, ток по фазам и перекос, потребляемая мощность, давление на конусе; строка с двигателем, регулированием, адресом и шильдиком. Пункт 5 чек-листа — по каждому вентилятору с перекосом; новые пункты 22 (настройки приводов), 23 (рекуперация), 24 (порядок наладки системы). Пункты 1–21 сохранили свои номера.
- **Старые проекты** переводятся автоматически: тип УВУ по проектным расходам, по вентилятору на сторону с прежними частотой, током и k конуса.

## Управление и связь, адресация (0.9)

- Один блок для вентилятора, контроллера УВУ и привода VAV/CAV (в карточке точки): питание (24 V AC / DC, 230 V AC), управление — Вкл/Выкл, 0–10 / 2–10 V DC (сигнал при минимуме / максимуме, обратная связь), Modbus RTU (адрес, скорость, чётность, стоп-биты, шина), Modbus TCP (IP, порт, Unit ID), BACnet MS/TP (MAC, Device Instance, скорость, Max Master, шина), BACnet/IP (IP, UDP-порт, Device Instance), MP-Bus (адрес, шина), другое; имя в GTB/BMS, примечание. У VAV/CAV также Vnom и режим при наладке (VAV / CAV / открыт / закрыт).
- **Проверка совпадений**: одинаковый адрес на одной шине (шина по имени, иначе — система), одинаковый IP:порт, одинаковый BACnet Device Instance — предупреждение у поля.
- **Отчёт**: в «Regelorganen» — Vnom и «Sturing / adres»; глава PDF и лист Excel **«Sturing en adressering» / «Adressering»** — все управляемые устройства по системам, с пометкой «DUBBEL ADRES».

## Каталог технических паспортов (ТФ) — этап 1

- **Где**: Настройки → «Каталог технических паспортов». Запись — это один типоразмер: производитель, тип/серия, вид (ирис, регулирующий клапан, CAV, VAV), DN. В записи также хранятся k по положениям (с отметкой, какое положение означает «открыт») или одно значение k на штуцерах, Qmin–Qmax и Δp min. Δp min задаётся постоянным или при Qmax; во втором случае программа пересчитывает его к проектному расходу как ~Q². Обязательно указываются ссылка на официальную ТФ и документ с датой.
- **Встроенные записи** взяты только из официальных документов (проверено 28.10.2026):
  - TROX IRIS Ø80–800 — «Innreguleringsdata for IRIS» от 06.11.2019, k в л/с по положениям 1–8, положение 1 = открыт;
  - Halton PRA Ø100–800 — таблицы k-factor на halton.com, открытие a = 1–6, a = 6 = открыт;
  - TROX TVR (VAV) NS 100–400 — паспорт PD-08/2026: Qmin–Qmax, Δpst,min при Qmax;
  - TROX RN (CAV) NS 80–400 — паспорт PD-06/2026: Qmin–Qmax, минимальный Δp 50 Па (NS 80 — 100 Па);
  - TROX VFC (механический CAV для малых расходов) NS 80–250 — паспорт PD-02/2026: Δp 30…500 Па, точность ≈ ±10 % от номинального расхода; Qmin–Qmax по размеру — крайние точки таблицы «Quick sizing» (80: 22–151, 100: 22–234, 125: 36–360, 160: 65–666, 200: 90–900, 250: 133–1332 м³/ч).
- **Δp max**: в записи можно указать наибольший допустимый перепад давления по ТФ. Если статическое давление перед CAV/VAV выше, в карточке давлений точки появляется предупреждение «имеется … Па > макс. … Па (техническая карта)».
- **Правка и копирование**: встроенные записи не редактируются. В Настройках группа встроенных записей раскрывается по размерам, у каждого размера есть кнопка «Копировать»: создаётся своя запись с теми же данными и пометкой «(kopie)» в типе. Своя запись редактируется («Изменить») и копируется (в списке или кнопкой «Копировать» в диалоге).
- **Свои записи** добавляются вручную («+ Запись») или через Excel: «Шаблон Excel / экспорт» → заполнить листы «Catalogus» и «k per stand» → «Импорт Excel». Встроенные строки (ID «lib:…») при импорте пропускаются. Строка с тем же ID или с тем же производителем, типом и DN заменяется. Свои записи хранятся на устройстве (общий каталог организации в облаке — этап 3).
- **Привязка**: в карточке точки у регулирующего органа (ирис, регулирующий клапан, CAV, VAV) есть список «Технический паспорт». Подходящий DN отмечен ★. При выборе:
  - заполняется «Модель / DN»;
  - у CAV/VAV заполняется Δp min при проектном расходе, и появляется предупреждение, если проектный расход вне диапазона регулятора;
  - для замера по k-фактору k берётся из таблицы по положению: для замера 1 — по «Положению до», для замера 2 — по «Положению после». «open» означает открытое положение по ТФ, промежуточные положения интерполируются.
  - Копия записи хранится в проекте (`p.cat`), поэтому файл проекта, пакеты бригад и отчёты переносят данные с собой.

- **Отчёт**: глава PDF «Technische fiches» и лист Excel с тем же названием. В них производитель и тип, данные, точки и источник с датой. Колонка k в «Inregelrapport lucht» — это k контрольного замера.

## Работа бригадами (пакеты)

Руководитель (координатор) ведёт мастер-проект: делит работу на пакеты, настраивает установки в заданное положение, собирает результаты.

1. Шаг «Проект» → карточка «Бригады и пакеты» → **+ Пакет для бригады** (или на шаге «Точки»). Выбираются фаза (первичный или контрольный замер), установка и направление, ветки или этажи / зоны, отдельные точки.
2. Вид пакета:
   - **файл приложения (.json)** — бригада открывает его через «Импорт» на своём телефоне, работает как в обычном проекте и на шаге «Сдача» сохраняет файл результата;
   - **замерочный лист Excel** — для субподрядчиков без приложения: печатается на A4 (альбом) или заполняется в Excel; язык листа — NL / FR. Кремовые ячейки — ввод, остальное защищено.
3. Руководитель загружает файл результата или заполненный лист в карточке «Бригады и пакеты» → предпросмотр: обновлено, новые точки, фото, конфликты (значение изменено и в проекте, и бригадой — выбирается, какое оставить). Повторная загрузка того же файла ничего не дублирует.

Права бригады: замеры, положения клапанов, примечания и фото; можно **добавлять** точки, решётки и арматуру (в листе Excel — пустые строки внизу каждой группы). Код, установка, ветка и проектный расход выданных точек — только для чтения; **удаление** — только у руководителя. Новые точки помечаются «новая», пока руководитель их не подтвердит.

Статус точки (вместо замера): **недоступна / отсутствует / не соответствует данным** — с примечанием. Такие точки не считаются незамеренными, в отчёте выводятся отдельным списком.

Каждый замер подписывается: кто, бригада, когда, с какого устройства и при какой частоте вентилятора; если частота установки потом изменилась — у точки появляется отметка «при … Гц». В отчёте — колонка «Gemeten door» и таблица «Ploegen en pakketten».

Поле **«Этаж / зона»** у точки (и колонка «Verdieping / zone» в шаблоне импорта) — для деления работ; на шаге «Точки» есть фильтр по зоне.

## Языки

- Интерфейс: Настройки → «Языки» или переключатель EN / NL / RU на главном экране. По умолчанию — английский.
- Отчёты: язык по умолчанию для новых проектов — в настройках; для проекта — на шаге «Отчёт» («Язык отчёта»). Excel, PDF и замерочный лист выводятся на выбранном языке; бельгийская терминология (pulsie / extractie, debietkap, AFREGELEN; pulsion / extraction, balomètre, À RÉGLER).
- Подсказки: рядом с полями показывается термин отчёта (например, «Flow rate · Debiet») — когда языки интерфейса и отчёта различаются, всегда или никогда.
- **Новый язык без изменения программы**: Настройки → «Языки» → «Шаблон: интерфейс» или «Шаблон: отчёты» → в Excel заполнить кремовую колонку translation (подстановки в фигурных скобках, например {n}, не переводить), вверху указать code (de, pl …) и name → «Импорт языкового пакета». Пакет хранится на устройстве; непереведённые строки показываются на исходном языке (EN для интерфейса, NL для отчётов). Готовый пакет можно передать коллегам тем же файлом (.xlsx или .json).
- Для разработчика: встроенные пакеты — файлы `src/i18n/ui.<код>.js` и `src/i18n/rep.<код>.js` в архиве исходников (`inregelaar-source-<версия>.zip`, в эту сборку не входят); новый файл подхватывается сборкой автоматически.

## Пожарные, запорные и обратные клапаны

- Это отдельный тип точки — «Пожарный / запорный клапан (на канале)». Такие клапаны не регулируют и не замеряют: пожарные клапаны разделяют этажи и помещения, запорные и обратные перекрывают ветку.
- Клапан ставится в дерево сети там, где он стоит на канале. «Стоит после узла» — это узел перед клапаном (например, CAV) или пусто, если клапан стоит сразу после вентилятора или магистрали. В блоке «За этим клапаном» отмечаются ветка, узлы или решётки, которые он питает. Пример: CAV-T3 → BK-T3 → IR-T3.1 / IR-T3.2 → решётки.
- Для расходов, сумм по slave и балансировки клапан «прозрачен»: master для IR-T3.1 по-прежнему CAV-T3.
- Положение во время замеров (открыт / закрыт) и состояние (исправен / неисправен) указываются на шаге «Арматура», в карточке «Пожарные и запорные клапаны», по этажам и зонам. Если клапан закрыт или неисправен, все точки за ним помечаются «за BK-…», в редакторе замера появляется предупреждение, а на шаге «Отчёт» — замечание.
- Данные пожарного клапана: граница (из → в), проход (стена / перекрытие / стенка шахты), класс EI, привод (термозамок 72 °C / 24 В / 230 В), концевые выключатели. Проверки: люк, табличка, проверка срабатывания, сигнал в АСУ / на пожарный пульт, кто проверял. Пустая проверка — не входила в вашу работу.
- В отчётах лист Excel и глава PDF «Brandkleppen en afsluiters» (FR: «Clapets coupe-feu et isolement») идут отдельно от «Regelorganen». В регулирующих органах остаются регистр, ирис, CAV/VAV и клапан пленума. В выводе есть фраза о положении клапанов.
- Клапан пленума (plenumregelklep) относится только к решёткам (вихревые и щелевые диффузоры). У узлов-воздуховодов его нет; в старых проектах и при импорте он заменяется на регулирующий клапан.
- Шаблон импорта: «Soort» = Afsluiter, «Regelorgaan» = Brandklep, «Master» = узел перед клапаном. У точек за клапаном в «Master» стоит код клапана. Необязательные колонки: «Grens van», «Grens naar», «EI-klasse», «Bediening». В замерочном листе положение клапана вписывается в колонку «Stand» как «Open / In orde» или «Dicht / Defect».

## Вход, регистрация и демо

- При первом запуске открывается экран входа: «Войти» или «Создать аккаунт» (e-mail и пароль: не меньше 10 символов, буквы и цифры). Аккаунты хранятся на сервере Supabase (ЕС), поэтому для входа нужен интернет. Дальше приложение работает и офлайн: сессия действует 14 дней без связи.
- **Подтверждение e-mail кодом (0.9.3).** После регистрации приходит письмо с 6-значным кодом, код вводится в приложении. Ссылок в письме нет: почтовые сканеры (Microsoft Safe Links и др.) открывают ссылки сами и подтверждали адрес без участия человека. Вход до подтверждения ведёт на экран кода; «Отправить код ещё раз» — новое письмо.
- **Сброс пароля кодом.** «Забыли пароль?» → «Отправить код» → код из письма и новый пароль → вход.
- После регистрации остаётся один шаг: принять приглашение своей фирмы или создать организацию. Создатель становится владельцем, пробный период 14 дней на 3 пользователей — **один раз на e-mail**: вторая организация того же человека создаётся без пробного периода.
- Владелец или администратор приглашает коллег в Настройках → «Аккаунт и доступ» (e-mail и роль). У приглашения есть **код** (вида `K7MP-Q4RX`): кнопка «Отправить код» открывает WhatsApp / почту (или копирует текст) со ссылкой на приложение, адресом и кодом. Коллега регистрируется с этим e-mail, подтверждает адрес и вводит код приглашения. После 5 неверных кодов приглашение закрывается.
- **Пароль и устройства** (Настройки → «Аккаунт и доступ»): смена пароля и «Выйти на всех устройствах» — на случай потерянного планшета.
- Если на сервере включена проверка на робота (Cloudflare Turnstile), она невидима: задачка появляется внизу экрана, только когда Cloudflare не уверен.
- **Демо для ознакомления: пользователь `demo`, пароль `demo`.** Без интернета и без сервера: пример проекта, все функции. Демо-проекты хранятся отдельно от проектов аккаунта, отчёты помечаются DEMO. Выход из демо — кнопка «Выйти из демо» на главной или в Настройках.
- Проекты пока хранятся на устройстве (синхронизация между устройствами — в следующей версии).
- **Автозаполнение при входе**: после входа предприятие (название, адрес, нижний колонтитул) заполняется из данных предприятия в активном стиле отчёта, а если в стиле их нет — названием организации. Техник — по аккаунту: имя, а если его нет — часть e-mail до «@». В Настройках под полями видно «по входу — можно изменить». Значение, изменённое вручную, сохраняется, пока входит тот же человек; при входе другого пользователя на этом устройстве поля заполняются заново. Новые проекты берут предприятие и техника из настроек.

## Безопасность веб-версии (0.9.3)

- Страница PWA разрешает только собственный скрипт приложения (по его хэшу), свои файлы, сервер Supabase, Google Fonts и Cloudflare Turnstile (Content Security Policy). HTML в импортированном Excel или в пакете бригады не может выполниться или отправить данные на чужой сайт. Все тексты проектов выводятся как текст (проверено автотестом с HTML во всех полях).
- В APK эта политика не ставится: Capacitor добавляет в страницу свой встроенный скрипт.
- Сайт на `bestof-bv.github.io` делит адрес (origin) со всеми другими сайтами GitHub Pages организации bestof-bv. Не публикуйте там другие сайты — или подключите собственный домен (например, `app.<ваш-домен>.be`).

## Иерархия master / slave

- Master — точка типа «Узел / воздуховод» (CAV, VAV, IRIS, регистр ветки, магистраль). У каждой точки поле «Подчинён узлу (master)»: один master — сколько угодно slave.
- Slave сам может быть master: CAV-T3 → IR-T3.1, IR-T3.2 → решётки T3.01…T3.03. В редакторе узла кнопка «+ Подчинённая точка» создаёт slave с той же установкой, направлением и веткой.
- Master без собственного замера получает расход = Σ slave (когда замерены все), без проектного расхода — Σ проектов slave; несовпадение Σ проектов с проектом узла подсвечивается.
- Балансировка идёт группами «slave одного master», от самого глубокого уровня вверх; индекс считается внутри группы.
- При удалении узла его slave поднимаются на уровень выше; при смене установки или направления ветка переносится целиком.

## Давления в воздуховоде

- Шаг «Замер 1»: карточка «давления в сети» по каждой установке и направлению — статическое давление (Па) перед каждым узлом и у дальних решёток, все клапаны открыты; внешнее давление вентилятора — в карточке установки.
- Индекс системы — точка с наименьшим |p|: самый нагруженный путь от вентилятора, эта ветка остаётся открытой.
- Потери: Δp от master = |p master| − |p точки| (до ближайшего замеренного master или до вентилятора) и Δp от вентилятора.
- «Замер 2»: повторное давление — рост потерь показывает, сколько «съел» прикрытый клапан. Для CAV/VAV укажите Δp min по данным производителя — при меньшем давлении точка помечается «Δp < мин.».
- В отчётах: Excel — лист «Kanaaldrukken» с формулами, PDF — глава «Kanaaldrukken»; в Inregelrapport — колонки Niv. и Master, отступ slave, Σ для master.

## Расчёты

| Метод | Ввод | Расход |
|---|---|---|
| Воронка / показания регулятора | Q, м³/ч | среднее значений |
| Анемометр × Aeff | v, м/с; Aeff, м² | Q = v · Aeff · 3600 |
| Δp × k-фактор | Δp, Па; k | Q = k · √Δp |
| Трубка Прандтля, траверс | pd, Па в точках; сечение | vᵢ = √(2·pdᵢ/ρ), Q = v̄ · A · 3600 |
| Траверс скоростей | v, м/с в точках; сечение | Q = v̄ · A · 3600 |

Десятичный разделитель — запятая или точка.

Шрифт PDF: Liberation Sans (подмножество, лицензия SIL Open Font License 1.1) — поддерживает латиницу с диакритикой (FR, NL, DE, PL …), кириллицу, Δ, √, ³.
